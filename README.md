# XAUUSD — универсальные модели реакций экономических отчётов

## Что делает комплект

`multi_event_reaction_analyzer.py` сканирует все CSV внутри `data/economic_data` и для каждой пары **валюта + название отчёта**:

1. Читает дату/время, Actual, Forecast, Previous из старого или нового формата Forex Factory.
2. Сопоставляет релизы с локальными минутными XAUUSD BID и ASK.
3. Повторяет принцип существующего Retail analyzer: база — закрытие M1-свечи, заканчивающейся в момент публикации; реакция считается относительно этой базы.
4. Рассчитывает реакции на 1, 5, 15, 30, 60 и 120 минутах.
5. Создаёт `event_reactions.csv`, `scenario_templates.json`, `group_stats.csv` и `analysis_report.md` отдельно для каждого отчёта.
6. Создаёт общий `model_catalog.csv`, `run_report.md` и выборку календаря на 25.11.2026.

Используется только XAUUSD. DXY/другие валютные пары не нужны.

## Важное ограничение исторических данных

Скрипт не может восстановить историю публикаций из истории котировок. Если в конкретном CSV отчёта календарная история начинается в апреле 2025 года, модель этого отчёта будет иметь выборку только с апреля 2025 года — даже если XAUUSD-котировки доступны с 2004 года. Это видно в `model_catalog.csv` и в каждом `analysis_report.md`.

В каталоге репозитория есть 612 групп событий. Сам `event_catalog.csv` может содержать устаревшие диапазоны дат: проверять фактический период нужно по строкам самих event CSV. Например, Core PCE имеет 237 релизов с 2007-02-01 по 2026-10-29; Prelim GDP — 238 строк с 2007-01-24 по 2026-11-16; Core Durable Goods — 238 строк с 2007-01-26 по 2026-10-27; Personal Income и Personal Spending — по 237 строк с 2007 года. Поэтому для этих отчётов доступна более длинная историческая выборка, а не только данные с 2025 года.

## Установка / запуск на Windows

Нужен Python 3.10+. Единственная зависимость — `tzdata`, чтобы корректно восстанавливать legacy-время через `America/New_York` на Windows.

```powershell
py -3 -m pip install -r .\requirements.txt
```

1. Распакуй комплект и скопируй все файлы из него в корень `mvp_xauusd_bot`: `multi_event_reaction_analyzer.py`, `run_all_models.ps1`, `run_wednesday_models.ps1`, `list_wednesday.ps1` и `wednesday_watchlist_2026-11-25.csv`.
2. Убедись, что свежие per-event CSV лежат в `data\economic_data`.
3. Скрипт автоматически ищет самый свежий `forex_factory_cache.csv` в `untitled\data`, `data` и корне репозитория и использует его как приоритетный источник для актуальных значений и будущих событий. В PowerShell из корня репозитория выполни:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\list_wednesday.ps1
```

Команда только выведет USD-события, которые есть в локальных календарных CSV на 25 ноября 2026 года. Если список пуст, сначала обнови `forex_factory_cache.csv`, затем запусти существующий `create_calendar_reports.py`, чтобы пересобрать `data\economic_data`. Даже при пустом focus-списке `run_wednesday_models.ps1` построит модели по именам из watchlist; но актуальные время/Forecast/Previous нужно проверить в свежем cache.

4. Для расчёта моделей только по отчётам из среды 25 ноября (включая их исторические релизы):

```powershell
.\run_wednesday_models.ps1
```

5. Для расчёта моделей по **всем** отчётам во всех 612 группах каталога:

```powershell
.\run_all_models.ps1
```

Ожидаемый путь к котировкам:

```text
E:\work\XAU_gold\XAUUSD\raw\BID\2026\11\XAUUSD_M1_BID_2026-11-23.csv
E:\work\XAU_gold\XAUUSD\raw\ASK\2026\11\XAUUSD_M1_ASK_2026-11-23.csv
```

Шаблон пути уже встроен. Если каталог отличается, передай `--xau-root` вручную.

## Запуск напрямую

```powershell
py -3 .\multi_event_reaction_analyzer.py `
  --economic-data-dir ".\data\economic_data" `
  --xau-root "E:\work\XAU_gold\XAUUSD\raw" `
  --calendar-cache ".\untitled\data\forex_factory_cache.csv" `
  --output-dir ".\output\event_models" `
  --focus-date "2026-11-25" `
  --focus-currency "USD"
```

Для всех валют в списке фокус-даты используй `--focus-currency ALL`.

## Как читать статистику

- `Actual - Forecast > 0` → `beat`; `< 0` → `miss`; `= 0` → `inline`.
- Beat/Miss отдельно делятся на small / medium / large по 33-му и 67-му процентилям сюрприза внутри этого отчёта.
- `p_up`, `p_down`, `p_flat` рассчитываются от всех наблюдений.
- `p_up_dir`, `p_down_dir` — условные вероятности направления при исключении flat.
- `flat_threshold` для каждого горизонта равен половине стандартного отклонения реакции XAUUSD в доступной выборке этого отчёта.
- При `N < 10` скрипт намеренно не публикует вероятности; при `10 <= N < 15` показывает предварительную статистику; от `N >= 15` — `reliable` по внутреннему порогу проекта, но это не гарантия точности прогноза.

## Технические предостережения

1. Одинаковые по времени публикации отмечаются в `co_released_events`. Если, например, Core PCE, GDP, Claims и Durable Goods выходят одновременно, отдельные модели этих отчётов не изолируют их причинное влияние. Для следующего этапа нужно отдельно оценить общий пакет публикаций.
2. Строки с multi-part значениями вроде `4.10|2.3` не переводятся в одно число и исключаются из простой модели surprise. Они остаются в исходном CSV.
3. Анализатор сохраняет строки с неполными XAU окнами в `event_reactions.csv` для диагностики, но не включает их в вероятностную модель.
4. Скрипт использует исторические даты и Actual/Forecast из календарных CSV. Для текущего предстоящего события строка должна присутствовать в календаре; `focus_events_2026-11-25.csv` покажет, что реально загружено.
5. Важно, чтобы BID и ASK были минутно синхронизированы и timestamps в UTC. Скрипт не подменяет недостающий BID или ASK данными другой стороны.

## Граница текущего этапа

Этот пакет выполняет локальную историческую подготовку моделей и формирует контрольный календарь. Он пока не разворачивает Render-сервисы, не собирает непрерывные live-котировки и не отправляет Telegram-сообщения. Это следующий этап после проверки сформированных `scenario_templates.json` и `event_reactions.csv`.
